# ADR-004. Прогноз просрочки по портфелю МСБ: месячный пакетный расчёт в контуре, выход - агрегат по сегментам, не оценка по заёмщику

**Статус:** принято
**Дата:** 2026-08-28
**Инициатива:** №4 «Прогнозировать годовой уровень просрочки по портфелю кредитов МСБ» ([триаж](../Task1/1_Триаж.md) → ML-кандидат)

## Контекст

Банк кредитует оборотные средства МСБ и теряет на невозвратах. Резервы, лимиты и ценообразование по сегментам планируются экспертно, без количественного прогноза с интервалом. Потребитель - риск-комитет. Постановка и готовность данных - [паспорт, разделы 2–4](Паспорт_разделы_2-5.md).

## Жёсткие ограничения

1. **Постановка портфельная.** Выход - агрегат по портфелю и сегментам. Использование оценки как основания для решения по конкретному заёмщику переводит инициативу в блокатор №12 (решение исключительно на автоматизированной обработке, затрагивающее права субъекта: среди заёмщиков ИП, по сделкам - поручители-физлица). Ограничение реализуется в выходном контракте: оценка по сделке не покидает расчётный контур.
2. Данные заёмщиков - ПДн и банковская тайна → обработка внутри контура.
3. Прогноз влияет на резервы → обязательна воспроизводимость: версия модели, версия данных и допущения хранятся вместе с числом.

## Сравнительные критерии

Калибровка и покрытие интервала → объяснимость для риск-комитета и надзора → устойчивость на сегментах с малым числом наблюдений → стоимость владения. Ранжирующая способность важна, но вторична: для резервов ошибка уровня дороже ошибки порядка.

## Рассмотренные варианты

| Вариант | За | Против | Почему отклонён или выбран |
|---|---|---|---|
| Экспертная экстраполяция винтажей (текущий процесс) | Дёшево, понятно риск-комитету | Нет интервалов, слабо ловит различия сегментов | **Baseline** - с ним сравниваем |
| Логистическая регрессия на скоринговых признаках | Прозрачна, устойчива на малых выборках | Ниже по качеству на нелинейных зависимостях | **В шортлисте** - как объяснимый эталон |
| **Градиентный бустинг** | Лучший результат на табличных данных | Требует калибровки и контроля утечки будущего | **Выбран основным кандидатом** |
| Модели выживания | Дают срок до события, а не только факт | Сложнее в интерпретации и сопровождении | **В шортлисте** - если важен момент наступления |
| Внешний сервис/готовая рейтинговая модель | Быстрый старт | Выгрузка ПДн заёмщиков; чужие допущения в основе резервов | **Отклонён** - ограничение 2 и требование воспроизводимости |
| Отдельный онлайн-сервис оценки | Пригодился бы кредитному конвейеру | Именно это и запрещено ограничением 1 | **Отклонён** |

**Процедура окончательного выбора.** Проверка на закрывшихся когортах с разделением **по времени** (обучение на ранних, проверка на поздних), плюс сегментные срезы по ОКВЭД, региону и размеру. Метрики - калибровка (Brier, reliability), покрытие интервала, абсолютная ошибка портфельного прогноза; на сделке - Gini как вспомогательная. Провал: не обгоняет экстраполяцию винтажей → модель не строится, процесс остаётся экспертным. Систематическое занижение на кризисных когортах → добавляется стресс-слой поверх модели, а не подгонка модели.

## Решение

- **Данные.** Источник ответа - реализованные просрочки и дефолты по историческим когортам; разметка не требуется. Вердикт готовности - **«можно начинать пилот»** при подтверждении объёма положительного класса; при малом числе событий вердикт понижается до «разрыв с планом закрытия» (мягкая метка 30+/90+, расширение горизонта).
- **Размещение.** Месячный пакетный расчёт на существующих мощностях DWH/аналитической платформы банка, без отдельного сервиса. Пилот и прод совпадают по контуру и различаются регламентом: версионирование прогнозов, автоматический бэктест на закрытых когортах, выгрузка в BI, аудит.
- **Модель.** Градиентный бустинг с калибровкой и агрегацией; детерминированные звенья - сборка когорт, интервалы, стресс-сценарии, границы правдоподобия. Оценка по сделке остаётся внутренним артефактом.

## Допущения

| Допущение | Источник | Критично для вывода |
|---|---|---|
| Историческая глубина покрывает 2–3 годовых когорты | оценка | Да |
| Число дефолтов достаточно для устойчивой оценки | неизвестно из кейса | **Да, определяет вердикт готовности** |
| Отчётность заёмщиков в архиве не искажена систематически | оценка (пересечение с №10) | Да |
| Макропеременные доступны в редакции на дату прогноза | оценка | Да - иначе утечка будущего |

## Риски и что с ними делаем

| Риск | Проявление | Что делаем |
|---|---|---|
| Смена макрорежима | Факт выходит за интервал | Триггер перекалибровки; стресс-слой поверх модели |
| Сползание постановки | Оценку по сделке просят использовать в решении по заявке | Архитектурный запрет на экспорт оценки по сделке; при запросе - остановка и обращение к юристам |
| Выжившая выборка | Прогноз применяют к потоку, которого модель не видела | Оговорка о применимости в отчёте риск-комитету; reject inference как отдельная работа |
| Искажённая отчётность на входе | Признаки врут, ошибка списывается на модель | Вариант модели без признаков отчётности как контроль; связка с инициативой №10 |
| Малые сегменты | Случайный разброс принимают за ошибку модели | Минимальный размер сегмента, ниже - fallback на экстраполяцию с пометкой метода |

## План выхода

Расчёт выполняется на собственных мощностях, на открытых библиотеках; витрина, признаки и бэктест - внутри банка. Зависимости от поставщика нет; смена аналитической платформы означает перенос кода расчёта, а не пересборку методологии.

## Триггеры пересмотра

- Смена макрорежима (ставка, отраслевой шок) - внеплановая перекалибровка.
- Выход банка в новый клиентский сегмент объёмом свыше 5 % портфеля.
- Факт вне интервала прогноза два периода подряд.
- Запрос на использование оценки в решении по конкретному заёмщику - остановка и обращение к юристам.
- Изменение определения события просрочки в учётной политике.
