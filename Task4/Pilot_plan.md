# План пилота - Флагман №1 «Выявление подозрительных операций»

Пилот существует не чтобы «показать, что модель работает», а чтобы **снять
критичные допущения TCO**, от которых зависит знак экономики (см. TCO §6).

---

## 1. Какие неопределённости проверяет пилот

Привязка к критичным допущениям расчёта:

| Неопределённость | Какое допущение проверяет | Как измеряем |
|---|---|---|
| Реально ли модель экономит время разбора | #1 (-30 %) | хронометраж разбора с карточкой vs без, A/B по аналитикам |
| Растёт ли доля подтверждённых в разобранной выборке | #3 precision | доля эскалаций и отказов в проведении на риск-ранжированной очереди vs текущей (по сумме) |
| Ловит ли модель схемы **раньше**, чем всплыли бы по сумме | эффект C | лаг между попаданием в очередь по риску и датой, когда операция всплыла бы по текущему порядку |
| Снижаются ли лишние приостановки/жалобы | #4, #5 | число приостановок и жалоб в пилотном сегменте vs контроль |
| Держит ли модель качество на реальном потоке, а не на отложенной выборке | - | стабильность метрик во времени, дрейф |
| Смещение отбора: модель обучена на непроверенном ≠ чистом | - | доля подтверждений среди операций, которые правила НЕ метили, а модель подняла |

---

## 2. Дизайн

- **Режим:** shadow → рекомендательный. Сначала модель считает score в тени
  (никаких действий), финмониторинг работает как обычно; сверяем ранжирование
  с фактическими исходами. Затем - рекомендательный режим: риск-очередь видна
  аналитику, но приостановку по-прежнему выносит человек.
- **Длительность:** 3 месяца (учитывая, что подтверждённые случаи «появляются
  спустя месяцы» - часть исходов дозреет уже после пилота, это закладываем).
- **Выборка:** контролируемое A/B. Часть потока помеченных операций
  ранжируется моделью, сопоставимая часть - как сейчас (по сумме). Аналитики
  распределены между ветками, чтобы исключить эффект конкретных людей.
- **Юридический контур:** приостановку всегда выносит человек (нет
  автоматизированного решения по субъекту - важно для ст. 22 152-ФЗ);
  установленная процедура ПОД/ФТ не отменяется, модель - вспомогательный сигнал
  поверх правил.

---

## 3. Критерии успеха (go)

Все три - одновременно, иначе экономика не сходится:

1. **Экономия времени ≥ 20 %** на разобранную операцию (допущение #1 закладывало
   30 %; порог go ставим ниже с запасом).
2. **Precision риск-очереди статистически выше** текущей: доля эскалаций/отказов
   в топе риск-очереди ≥ в 1,25× относительно очереди по сумме.
3. **Раннее выявление подтверждено**: медианный лаг обнаружения в риск-ветке
   меньше, чем в контроле (хотя бы качественно, на дозревших исходах).

## 4. Guardrails - что НЕ должно ухудшиться

Охраняют не только качество модели, но и клиента и процесс:

| Guardrail | Порог | Почему |
|---|---|---|
| Доля лишних приостановок честных клиентов | **не выше** текущей (450/600 снимаются) | нельзя оплатить эффект блокировками честных |
| Число жалоб в пилотном сегменте | **не выше** контроля | клиентский вред - стоп-фактор, а не строка эффекта |
| Доля снятых приостановок (ложные срабатывания) | не растёт | прокси качества для клиента |
| Полнота охвата ПОД/ФТ | не ниже текущей | обязанность банка, не бизнес-инициатива - процедура не деградирует |
| SLA очереди / глубина очереди человека | не хуже | нельзя завалить службу «умной» очередью |
| Доля операций в зоне воздержания | ≤ 15 % | если модель «воздерживается» слишком часто - она не помогает |
| Латентность/доступность сервиса | в SLA | отказ сервиса не должен блокировать разбор |

## 5. Критерии остановки (честно закрываем)

Проект закрывается или откатывается, если по итогам пилота:

- **Экономика не сходится:** экономия времени < 20 % **и** precision-lift < 1,25×
  → base-case TCO уходит в устойчивый минус (см. сценарий «только труд» = -9,8 млн).
- **Любой guardrail пробит устойчиво** (не разовый выброс): растут приостановки,
  жалобы или падает охват ПОД/ФТ. Клиентский или регуляторный вред не
  компенсируется деньгами - это безусловный стоп.
- **Юридический блок:** комплаенс/DPO/юристы дают отрицательный вердикт по
  правовому основанию обработки в проде.
- **Данные не позволяют учиться:** слабые следы («эскалировано», «исход»,
  «подтверждено») не дают обучаемого сигнала выше базлайна правил → нет предмета
  для модели, задача закрывается правилом.

Если результат в «серой зоне» (часть критериев выполнена) - не масштабируем, а
продлеваем пилот с уточнёнными допущениями; масштабирование только при полном go.
